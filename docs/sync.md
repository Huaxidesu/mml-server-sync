# 同步规则

只读取 MML 生成的 `server.json`（`Files` / `Archives` / `Base`），同步游戏目录；
不兼容 HMCL `server-manifest.json` 或其他清单格式。

## 清单指纹

发布目录里有 `server.json.sha1` 时，先取它和本地清单比 SHA-1：

- 一致 → 跳过整份下载；
- 没有这个文件、取不到、内容不是 40 位哈希，或本地还没有清单 → 照旧下载 `server.json`。

指纹只比**字节**：清单内容改过就要重下一次。`--force` 不看指纹。
比对对象是**解压后**的清单字节，也就是 `last-manifest.json` 里存的原文。

## 版本

清单的 `PackVersion` 与上次状态相同 → 直接跳过（`--force` 可强制）。

## 文件比对

`Files` 里的相对路径按 SHA-1 比对（条目没有 SHA-1 时用 SHA-256）：

- 本地缺失或哈希不同 → 下载；
- 本地一致 → 跳过。

禁用后缀也算「已安装」：`.disabled`（以及旧版 `.disable`）会被当作同一份文件按内容比对，
不会因为文件名变了就重新下载。

## 按清单归位

内容一致时只改文件名，不产生下载：

| 本地状态 | 清单状态 | 结果 |
|---|---|---|
| `x.jar.disabled` / `x.jar.disable` | 必装 | 改名为 `x.jar` |
| `x.jar.disabled` | 自选 · 已勾选 | 改名为 `x.jar` |
| `x.jar` | 自选 · 未勾选 | 改名为 `x.jar.disabled` |

内容不一致时先下载到目标路径，再清掉同一模组的其它变体（含旧后缀 `.disable` 残留）。
清单里带 `Optional` 的条目按玩家的勾选安装，详见 [optional-mods.md](optional-mods.md)。
改名失败（文件被占用、权限不足）只记日志并保留原状，下次启动重试，不会中断更新。

## 删除

旧清单有、当前清单没有的受管文件会删除：

- 一条规则覆盖三种状态：启用名与它的 `.disabled` / `.disable` 副本一并删除；
  清单里仍在的路径连同禁用副本不删，因此不会出现「刚下载就被删」；
- 同一项目编号换了路径时，删除旧路径；
- 配置压缩包条目从清单移除时**不会**删除已解压目录（避免误删玩家的 config）；
- 清单之外的用户文件不动。`--no-delete` 可只跳过删除步骤。

命中旁文件 `Ignore` 规则的路径不删；发布端 `Removed` 列表另见下一节。
旁文件不可用时本节列出的删除**全部不执行**，下载照常（见下一节）。

## 同步规则旁文件

发布端可在清单同目录放 `server.json.sync.json`，客户端按 `<清单 URL>.sync.json` 读取：

```json
{
  "Removed": ["mods/old.jar"],
  "Ignore": ["options.txt", "shaderpacks/", "mods/*自选*"]
}
```

- `Removed`：历史废弃路径。与本地是否保存过旧清单无关，首次同步与跨版本升级都能清理；
  `mods/a.jar` 一条即可覆盖 `a.jar`、`a.jar.disabled` 与 `a.jar.disable`；
  当前清单里仍存在的路径（含其 `.disabled` 副本）、更新器自身 jar、归档目录内的路径、
  目录与通配写法、越界路径一律不删，文件不存在时静默跳过。路径比较统一分隔符与大小写，
  `./mods/a.jar` 与 `mods//a.jar` 视为 `mods/a.jar`。
- `Ignore`：屏蔽规则（目录前缀 / 通配 / 精确，忽略大小写）。命中的文件不下载、
  不覆盖、不参与自选模组改名，也不被 `Removed` 或旧清单差异删除；`.disabled` 变体
  按原路径判断。只有 `*` 与 `?` 是通配符，方括号按字面处理。
- 旁文件缺失、返回网页或格式错误时，本轮**不执行任何删除**（下载照常），日志会提示
  「同步规则旁文件不可用」。这样一次请求失败不会把玩家的私有文件当成「旧有新无」删掉。
- 只在真正执行同步时读取；清单指纹命中与 `PackVersion` 未变两条提前返回不读取，
  因此发布端修改旁文件必须同时递增 `PackVersion`。

`server.json` 本身不增加字段，MML 启动器的 `server.json.sha1` 快速通道保持有效。

## 配置压缩包

- 只支持 zip；按目标目录深度从浅到深解压。
- `Over=true` 先清理旧目录再解压（仅在压缩包仍在清单里时生效）：清理时保留
  命中 `Ignore` 的文件，解压时也跳过这些条目，归档因此无法覆盖屏蔽项。
- **空压缩包（0 个条目）+ `Over=true` = 显式删除该目录**：发布端要删旧目录时发一个
  空 zip 当「墓碑包」，客户端删完不会留下空目录。**存在屏蔽规则时不执行**——
  整目录删除无法保证屏蔽项不动，这类实例应改用逐文件通道清理。
- 把条目从清单删掉**不会**删除已解压目录；要清理旧目录用上面的墓碑包，或手动删除。
- 同名、同目录、同哈希且目标目录还在时可以跳过。
- 归档是「整包替换目录」的语义，**不受旁文件是否可用的影响**：旁文件读不到时照旧清空
  目录再解压，保证其他整合包的 zip 用法不变；读得到且 `Ignore` 非空时才保留屏蔽项。

## 基础包

只在第一次同步（状态里没有 `Base`）时下载并解压到 `baseDir`；之后即使清单里仍有
`Base` 也不会重复下载。

MML 的 `server_instance_ids.json`、`server.json`、`game.json`、`icon.png` 等元数据
不会被基础包覆盖；基础包里有这些文件会直接报错。

## 状态文件

默认状态目录 `<game-dir>/.mml-server-sync`：

```text
last-manifest.json    上次同步的清单原文（指纹比对、旧清单读取）
optional-state.txt    自选模组的选择记录
optional-prompt.txt   自选模组「每次启动弹窗」开关（suppress=1）
mml-server-sync.log   同步日志
tmp/                  配置包 / 基础包的下载中转
```

第一次运行时如果状态不存在，会尝试用实例根目录的 `server.json` 作为旧清单；之后只读写
状态文件，不会改 MML 的 `server.json`。

## 下载与落盘

- 单个文件下载到目标同目录的 `<文件名>.part`，边下边算 SHA-1 / SHA-256；
  哈希对上才 `Files.move(..., ATOMIC_MOVE)` 覆盖目标，失败时退化为普通 move。
- 下载失败或取消时删掉 `.part`，**目标文件保持旧版本**，不会出现半截文件；
  进程被强杀时残留的 `.part` 会在下次下载前清掉。
- 没有断点续传：中断后下次整份重下。
- 清单类请求默认请求 gzip（服务端支持时 8 MB → 约 1 MB），并按 `Content-Encoding` 解压；
  文件下载不请求压缩，避免进度百分比与哈希失真（服务端强行压缩时仍会正确解压）。
- 配置压缩包与基础包先下到 `tmp/` 再解压。**解压不是原子操作**：中途断掉会留下部分目录，
  下次启动重新下载、重新解压。

## 已知边界

- 不会安装 Java、加载器或游戏本体，只更新实例文件。
- 不会执行 MML 的模组依赖检查、在线信息回写、实例设置回写。
- 只支持 zip；配置包是 tar.gz / 7z 时需要自行转换或扩展 `Fs.extractZip`。
- CurseForge 条目没带 URL 且没有 API Key 时依赖 CDN 命名规则，可能个别文件失败。
- 自定义条目（清单里没有项目编号）的身份按路径算，见 [optional-mods.md](optional-mods.md#已知限制)。
